VANILLA ROOM OVERRIDES
======================

The Chandlery's Lionsmith module supports modifying existing base-game rooms.
This is done by adding an override definition to the "terrain" array in your mod's terrain JSON file.

RESOURCE
--------
For room IDs, sphere IDs, seed IDs, and position data for every base-game
room, see:

    publicdocs/VanillaRoomReference.md

Each room entry lists the Room ID, Terrain Recipe, sphere IDs, types,
positions, sizes, the verb each workstation seeds, aspect requirements, and
seeds. Use those IDs directly in your override definitions.


BASIC STRUCTURE
---------------

An override is a normal terrain definition with "override": true and an
"id" matching a base-game room ID. Only the fields you specify will be
changed; omitted fields are left intact.

    {
      "terrain": [
        {
          "id": "<base-game-room-id>",
          "override": true,
          // ... fields to change ...
        }
      ]
    }

Example:

    {
      "terrain": [
        {
          "id": "pantry",
          "override": true,
          "sprite": "custom_pantry",
          "aspects": { "nectar": 2 }
        }
      ]
    }


1. CHANGING SPRITES
-------------------

Set custom unshrouded and/or shrouded sprites. Sprites are loaded from
"images\terrain\<path>" in your mod's images folder.

    "sprite": "<path-without-extension>",
    "shroudsprite": "<path-without-extension>"

If omitted, the existing sprite is left untouched. No placeholder is
generated if the sprite is not found (unlike new custom rooms, which
fall back to a black placeholder).

Example:

    "sprite": "pantry_alt",
    "shroudsprite": "pantry_alt_shrouded"


2. MOVING THE ROOM
------------------

Change the room's position on the map by setting posx and posy. Omit
either to leave the current position unchanged.

    "posx": <float>,
    "posy": <float>

Room positions signify the coordinates of their bottom left corner.
VanillaRoomsReference gives base room coordinates in the same scheme.

Example (from VanillaRoomReference.md, the pantry is at posx=-820, posy=1480):

    "posx": -820.0,
    "posy": 1480.0


3. CHANGING ASPECTS
-------------------

Replace the room's aspects entirely. If omitted, existing aspects are
kept. If set to an empty object {}, all aspects are cleared.

    "aspects": { "<aspect-id>": <level>, ... }

Example:

    "aspects": { "nectar": 2, "heart": 1 }


4. ADDING UNLOCK RECIPE
-----------------------

Change the requirements to unlock the room. The unlock recipe is
registered under "terrain.<room-id>" and replaces the base-game recipe.

    "unlockrecipe": {
      "label": "<string>",
      "preface": "<string>",
      "startdescription": "<string>",
      "description": "<string>",
      "aspects": { "<aspect-id>": <level>, ... },
      "essential": { "<aspect-id>": <level>, ... },
      "forbidden": { "<aspect-id>": <level>, ... },
      "warmup": <int>
    }

Example:

    "unlockrecipe": {
      "label": "Clean the Pantry",
      "preface": "Pantry",
      "startdescription": "Time to clear out this mess.",
      "description": "The shelves are dusty but usable.",
      "aspects": { "knock": 2, "nectar": 2 },
      "warmup": 30
    }


5. ADDING CONNECTIONS
---------------------

Register room-to-room connections so that unshrouding this room
automatically unseals connected rooms.

    "connectedto": ["<other-room-id>", ...]

This replaces any existing connections for this room in the connection
registry. If omitted, existing connections are left untouched.

Example:

    "connectedto": ["kitchen", "nave"]


6. REMOVING SPHERES
-------------------

Hide a sphere (slot, shelf, workstation, comfort, or wall art) from the room.

    "contents": {
      "remove_spheres": ["<sphere-spec-id>", ...]
    }

The sphere ID is the spec ApplyId shown in VanillaRoomReference.md (e.g.
"ComfortSlotDocBag", "ThingSlotBedsideTable"). Find the exact ID in the
room's entry.

Example:

    "contents": {
      "remove_spheres": ["ComfortSlotDocBag"]
    }


7. REPLACING SEEDS ON AN EXISTING SPHERE
----------------------------------------

Change the items that spawn in an existing sphere. List the sphere
definition under "spheres" with the matching "spheretype", providing only
the "id" and "seeds" fields. All other fields (posx, posy, etc.)
are left unchanged.

    "contents": {
      "spheres": [
        {
          "id": "<existing-sphere-spec-id>",
          "spheretype": "normal",
          "seeds": [
            { "id": "<element-id>", "posx": <float>, "posy": <float> },
            { "id": "<element-id>", "side": "left" }
          ]
        }
      ]
    }

The "id" must match the sphere's spec ID from VanillaRoomReference.md exactly.
The "seeds" array fully replaces all existing seeds on that sphere.

Seed entries support:
- "posx", "posy": position relative to the sphere's anchor point,
  increasing to the right and upward. If both are omitted, the item spawns
  at the centre of the sphere.
- "side": "left" or "right" (positions at the edge, for shelves)
- "anchor": which point of the item the "posx"/"posy" coordinates refer to.
  Defaults to "bottomleft" (the item's bottom-left corner). Other values:
  "center" (or "centre"), "bottomright", "topleft", "topright".

Example (replacing the seeds on ThingSlotNatanDesk in motleytower3):

    "contents": {
      "spheres": [
        {
          "id": "ThingSlotNatanDesk",
          "spheretype": "normal",
          "seeds": [
            { "id": "candle.holderthree", "posx": 10.545, "posy": 12.5 },
            { "id": "typewriter", "posx": 30.545, "posy": -2.5 }
          ]
        }
      ]
    }


8. OVERRIDING EXISTING SPHERE PROPERTIES
-----------------------------------------

In addition to replacing seeds, you can change an existing sphere's
position, size, aspect requirements, label, description, and drag/glow
behaviour. List the sphere under "spheres" with its existing "id" and
"spheretype" and the fields you want to change. Omitted fields are left
unchanged.

    "contents": {
      "spheres": [
        {
          "id": "<existing-sphere-spec-id>",
          "spheretype": "normal | bookshelf | comfort | wall",
          "label": "New Display Name",
          "description": "New tooltip",
          "posx": 100.0,
          "posy": 120.0,
          "width": 90.0,
          "height": 18.0,
          "required": { "<aspect>": 1 },
          "essential": { "<aspect>": 1 },
          "forbidden": { "<aspect>": 1 },
          "lockdrag": true,
          "showglowonhover": false,
          "showinteractionglow": false,
          "seeds": [ ... ]
        }
      ]
    }

- posx, posy: position of the sphere's bottom-left corner, relative to
  the room's bottom-left corner (Y increases upward), in the same scheme
  as VanillaRoomReference.md.
- width, height: sphere dimensions.
- required / essential / forbidden: replace the sphere's aspect
  requirements. Set to {} to clear them.
- label / description: replace the sphere's tooltip text.
- lockdrag: if true, items in this sphere cannot be dragged out.
- showglowonhover / showinteractionglow: toggle the sphere's highlight/glow.
- seeds: replaces all existing seeds (see section 7).

Note: the "greedy" property is not supported for room spheres

9. ADDING NEW SPHERES
---------------------

Add a brand-new sphere (slot, shelf, comfort spot, or wall art) to an
existing room. Use an "id" that does not match any existing sphere in the
room.

    "contents": {
      "spheres": [
        {
          "id": "<new-sphere-id>",
          "spheretype": "normal | bookshelf | comfort | wall",
          "label": "Display Name",
          "description": "Tooltip description",
          "posx": 100.0,
          "posy": 120.0,
          "width": 90.0,
          "height": 18.0,
          "required": { "<aspect>": 1 },
          "essential": { "<aspect>": 1 },
          "forbidden": { "<aspect>": 1 },
          "lockdrag": false,
          "showglowonhover": false,
          "showinteractionglow": false,
          "seeds": [ ... ]
        }
      ]
    }

All sphere fields from CustomRoomCreation.txt are supported. posx, posy,
width, and height default to 0/0/120/120 if omitted.

The new sphere is cloned from an existing sphere of the same type. A sphere
of the same type in the target room is preferred; if none exists there, a
matching sphere from any other room in the game is used as the template.

10. ADDING NEW WORKSTATIONS
---------------------------

Add a workstation (FitmentWorkstationSphere) to an existing room.

    "contents": {
      "workstations": [
        {
          "id": "<new-workstation-id>",
          "verb": "<verb-id>",
          "posx": 270.0,
          "posy": 200.0,
          "width": 100.0,
          "height": 100.0
        }
      ]
    }

- "verb" is the verb ID to seed this workstation with. The sprite is
  resolved from the verb, as described in CustomRoomCreation.txt.
- To customize the workstation's image, install the Dappled Mask mod and
  place the image in `images/fitments/{verbId}.png` (the image name must
  match the verb ID).
- The workstation's image is pinned to the bottom-left corner of the sphere
  and scaled until it hits the sphere's edge, preserving its aspect ratio.
  As such, for custom images, it is recommended to make the sphere the same
  aspect ratio as the base image to make sizing easier.

Note: the "verb" field is only applied when the workstation is newly added
to the room — the verb of an existing vanilla workstation cannot be changed
in place. To swap a workstation's verb, remove the vanilla workstation with
"remove_spheres" (section 6) and add a new one at the same position with the
desired verb. A hidden workstation's verb token does not spawn, so the
replacement takes over cleanly. Give the replacement a new "id" that does
not match the removed workstation's spec ID.


COMPLETE EXAMPLE
----------------

This override targets motleytower3 (Motley Tower: Regensburg Room). It
changes the sprite, moves the room, adds moth aspect, adds a connection
to the nave, changes the unlock recipe, removes the doc bag comfort
sphere, and replaces the seeds on Natan's desk.

    {
      "terrain": [
        {
          "id": "motleytower3",
          "override": true,
          "sprite": "motley_tower_alt",
          "posx": 460.0,
          "posy": 1560.0,
          "aspects": { "moth": 1 },
          "connectedto": ["nave"],
          "unlockrecipe": {
            "label": "Motley Tower: Regensburg Room",
            "preface": "Motley Tower: Third Floor",
            "startdescription": "Time to clear the miasma.",
            "aspects": { "heart": 6, "sky": 6 },
            "essential": { "assistance": 1 },
            "warmup": 60
          },
          "contents": {
            "remove_spheres": ["ComfortSlotDocBag"],
            "spheres": [
              {
                "id": "ThingSlotNatanDesk",
                "spheretype": "normal",
                "seeds": [
                  { "id": "candle.holderthree", "posx": -20, "posy": 0 },
                  { "id": "typewriter", "posx": 20, "posy": 0 }
                ]
              }
            ]
          }
        }
      ]
    }


NOTES
-----
- The "override": true flag is required. Without it, the definition
  is treated as a new custom room to create.
- Omitted fields are never changed. Only explicitly provided fields
  are applied to the existing room.
- Content overrides (removing spheres, changing seeds or sphere
  properties, and adding spheres/workstations) take effect when the room
  is populated. As with new rooms, mid-game changes are not guaranteed to
  apply until a new game.
